01Smart Document Assistant

Ask a question of your documents and get an answer that names the page it came from. An answer you cannot trace back to a page is worth very little when you are checking a contract — so citation is not a feature here, it is the constraint.

Ask

How this works, in four steps

  1. Extract — text out of the file, keeping the page number (core/docs.py).
  2. Chunk — split on sentence boundaries, ~1,200 characters with 150 of overlap. Splitting mid-sentence is the classic RAG bug: the excerpt reads as a fragment and the model fills the gap by inventing. The overlap means a fact sitting on a chunk boundary survives whole somewhere.
  3. Embed — each chunk becomes 3,072 numbers describing its meaning. Your question becomes 3,072 numbers the same way, with a different task type — using the same one for both measurably degrades retrieval.
  4. Retrieve and answer — cosine similarity picks the closest chunks (core/vectors.py), and only those reach the prompt.

The model never sees your whole document. It sees five paragraphs and a rule saying it may not go beyond them. That is why it can say “that isn’t in the documents you uploaded” instead of guessing.

The index is saved to data/doc_index/, so a restart does not re-embed — and re-pay for — the same PDF.

Known limits

  • No OCR. A scanned PDF has no text layer. This says so rather than returning nothing.
  • Indexing is one embedding request per chunk, so a long PDF takes a minute. Deliberate: the batch endpoint fails the whole batch on one bad input, and a 60-page PDF is exactly where one bad chunk is likely.
  • DOCX has no page numbers until it is rendered, so it cites the filename only. A guessed page number is worse than none.
