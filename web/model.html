03Custom Trained Model

Not an API call. TF-IDF and logistic regression written out in numpy and trained on 5,574 real hand-labelled SMS messages, on this laptop, with the test set held out before a single weight was updated.

The two things that actually moved the numbers

1 · Feature engineering. Every phone number in the dataset is a token seen once, so it gets pruned and the model learns nothing from it. Collapsing all of them into a single __num__ symbol — and all links into __url__ — gives the model a feature it can learn. Those two hand-made tokens came out as the top two spam indicators. A library cannot do this for you; it depends on the data.

2 · Class weighting. Only 13.4% of the dataset is spam, so an unweighted model minimises loss fastest by leaning towards "ham". That looks fine as accuracy and terrible as recall: the first run scored 96.95% accuracy but only 76.64% recall — it was missing a quarter of real spam. Weighting each spam example by n_ham / n_spam makes a missed spam cost as much as a false alarm, and recall went to 97.08%.

Why the baseline is on the page. Always predicting "ham" scores 87.71% on this test set. Any accuracy figure quoted without that number beside it is not telling you anything.
